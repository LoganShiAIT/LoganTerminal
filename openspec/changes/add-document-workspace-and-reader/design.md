## Context

本轮依据 proposal.md 的三个能力，改进工作区界面与 Markdown 阅读。现有 App 永久挂载全部终端标签，PaneTree 将叶窗格展平为稳定 keyed siblings，attachPtySession 的清理会杀死 PTY。因此，引入文档时最关键的架构约束是保持终端组件身份和挂载位置。

当前 ptyStore 同时管理终端树和活跃标签，TabBar、快捷键、素材插入与文件搜索直接读取 getActiveLeaf。MarkdownPreview 调用 math.ts，把公式替换为占位符，经 marked 解析后再插回 KaTeX HTML；图片目前只输出替代文字。ReviewPanel 已提供文本文件加载与编辑，MathPanel 提供可编辑公式草稿，Rust fs 文本读取上限为 1 MiB。

Pebrel 提供产品设计参考：文档成为主内容、目录与正文分离、阅读列居中、正文与终端使用不同排版。其 GPUI／Rust 数学管线不属于本轮实现路径。

## Goals / Non-Goals

**Goals:**

- 让文件文档与手动捕获的终端文本拥有独立标签及终端旁阅读入口。
- 在浅色、深色和中文内容下形成一致、可核验的阅读体验。
- 明确区分终端焦点、文档焦点和命令目标，避免文档导航误操作后台终端。
- 在同一解析结果上提供正文、目录、代码与公式操作，复用已有渲染依赖。
- 保留终端、素材、文件审阅、Math 草稿及其现有快捷操作。

**Non-Goals:**

- Agent Hook、自动回答捕获、AI 对话接续、PTY 保活、SSH/SFTP 和全局唤出。
- 原生 GPUI 迁移、完整 TeX 编译器、网络图片加载、公式图片导出、所见即所得编辑。
- 大文件平台和全应用任意拖拽布局；本轮文档上限沿用 1 MiB，正文采用普通 DOM，虚拟列表留待实际性能证据支持。

## Decisions

### D1: 工作区协调层独立于终端树

新增 workspaceStore 管理有序工作区条目、当前条目、阅读区布局与焦点；新增 documentStore 管理文档记录。终端条目引用现有 terminalTabId，文档条目引用 documentId，ptyStore 继续独占终端树与 PTY 状态。文档不伪装成 LeafPane，也不进入 Agent 总览、广播列表或 worktree 操作。

每个终端条目最多连接一个 companionDocumentId，并保存阅读区比例。文档记录分两类：文件记录包含规范绝对路径、baseDir、加载版本与内容；文本快照包含不可变文本、标题、来源类型、捕获时目录、窗格／标签来源和时间。多个视图引用同一文件文档记录；视图滚动和焦点独立。

工作区协调模块负责终端条目的增删同步，统一导航、关闭、排列与焦点入口。新建终端、Agent launcher、fleet、worktree、attention/dashboard 跳转都通过协调入口激活对应终端条目；仅订阅新增标签不足以覆盖已有终端跳转。终端属性、叶状态和输出更新不会改变工作区导航。保留 ptyStore 的领域 API，避免把文档状态混入 paneTree。

替代方案：把文档加入终端叶联合类型会将终端假设扩散到广播、Agent、git、关闭与快照逻辑；本轮采用独立协调层减少改动范围。

### D2: 固定挂载位置承载全文与终端旁阅读

App 继续在同一稳定父层中按 terminalTabId 渲染终端标签容器。选择文档标签仅隐藏终端容器。终端旁阅读通过缩窄对应终端容器并在主区域增加平级 DocumentReader 容器完成，不把 Terminal 或 PaneTree 移动到新父层。分隔线调整宽度后使用现有 fit／resize 流程更新 PTY 尺寸。

阅读区位于当前终端标签右侧，比例限制在 0.25–0.65，默认 0.45。关闭阅读区只解除关联，文档标签仍保留；关闭文档标签则移除全部关联；关闭终端标签按原有规则处理其 PTY，独立文档仍保留。比例调整、隐藏、显示和阅读主题切换不得触发 PTY dispose。

当扣除导航后的主区不足 760 CSS px 时，阅读分屏暂时显示为全宽文档视图，并提供返回终端按钮；保留原关联与比例，变宽后恢复。终端窗格缩放与阅读区互不覆盖，pane zoom 只作用于左侧终端树。

### D3: 显式焦点决定操作目标

工作区焦点区分 terminal(paneId) 与 document(documentId, placement)。读文档时，旧 ptyStore.activeTabId 仅保留最后终端上下文，不能作为写入／关闭／搜索的授权目标。统一 getFocusedTerminalTarget 和工作区命令路由，所有 keystroke、termBus、素材点击、Shift-drop、文件搜索路径插入、cd、广播和终端关闭操作都使用可见且聚焦的终端目标。

- 标签循环、数字跳转及 TabBar 拖动按混合工作区顺序执行。
- Mod+Shift+W 在文档标签关闭文档，在阅读区关闭阅读区，在终端保留关闭窗格行为。
- Mod+D／Mod+Shift+D、终端清屏、终端搜索、提示符跳转、广播等仅在终端聚焦时执行；读文档时相关命令隐藏或禁用，不落到后台 PTY。
- Mod+T、明确的启动 Agent／新终端操作仍可创建终端；以文件文档父目录、快照捕获目录或最后终端目录作为起点，并切换到新终端。
- 阅读区提供返回终端按钮，重新激活并聚焦其终端活动叶；打开 palette／finder 后关闭弹层恢复打开前的焦点，不强制 focus xterm。
- 文件树、文件搜索的浏览上下文可使用文档 baseDir；正文不具有目录时回落最后终端上下文，但浏览上下文与写入目标分离。
- StatusCluster 在独立文档视图显示文档来源／加载状态，不显示可操作的旧终端 git／广播状态；Agent 活动仍可通过总览定位。

文档内可选中和复制文本，原文只读，不拦截普通文本选择快捷键。本轮阅读器不新占用 Mod+F；该按键不得触发隐藏终端搜索，文档专用查找后续扩展。

### D4: 显式打开入口与只读阅读器

文件树提供 Markdown 文件的阅读按钮，文件搜索增加明确的阅读动作，保留原 Enter reveal、Mod+Enter insert、Alt+Enter cd、Shift+Enter attach 语义。ReviewPanel 增加在主区阅读及在终端旁阅读入口，不改变原编辑流程。文件加载按规范绝对路径去重，通过 Rust canonicalize 处理路径别名；Windows 保留规范路径语义，不对 POSIX 路径盲目转小写。

干净 Review 文件打开文件文档；未保存草稿打开不可变 draft 快照，清楚显示未保存草稿及来源路径，不写文件、不丢弃原稿，不与磁盘文档去重。Math 草稿同样通过快照推广至主区，保留原面板内容。

终端阅读命令通过已有 termBus 增加捕获请求：优先当前选区，无选区时使用 shell.selectLastOutput。先取得非空文本再创建快照，标明选区或上一条命令输出；不声称这是完整 AI 回答。OSC 133 无可用输出标记时给出选择文本后重试的提示，不猜屏幕内容。文件文档和文本快照都显示原文／预览切换；文件文档提供重新加载，编辑继续使用现有 ReviewPanel。

### D5: 共享 marked + KaTeX 文档模型

在现有 math.ts 基础上提取共享解析模块，仍优先隔离代码和数学，再把普通 Markdown 交给 marked。输出包含渲染正文、顺序标题索引和交互元数据：标题 id／层级／文本，代码 id／原文，公式 id／原始 TeX／display，图片 id／目标／替代文字。相同解析结果供阅读器正文与目录使用，保留 renderMathMarkdown 字符串 API 为旧 Math／Review／hover 调用适配。

标题 ID 按文档顺序生成稳定、唯一的本地 ID，支持重复标题与中文；无需把标题文本拼成文件路径。目录点击滚动当前读视图，预览重建后按可用 heading id 恢复位置，原文切换保留文档内容与视图状态。KaTeX 继续负责 DOM 数学排版，现有 $VAR／代码围栏防误判、HTML 字面显示和链接由 OS 打开行为保持。

文档读视图提供代码原文复制、块公式原始 TeX 复制，按钮以 hover／focus 出现，反馈保持轻量。普通公式宽度不足时横向滚动，不无限缩小字号；超宽表格与代码同样在各自内容区滚动。本轮不实现公式位图导出。

### D6: 图片依据不可变来源目录解析

MarkdownPreview 接受可选 baseDir 和阅读上下文，不读取全局当前 shell cwd。文件文档使用文件父目录，快照使用捕获时目录。支持相对图片路径、绝对本地路径和 file URI，通过共享路径解析 helper／Rust 接口返回有效本地路径，再使用 convertFileSrc 与现有 asset protocol；复用已有图片 lightbox。

远程 http(s) 图片保留替代文字与显式外部打开入口，维持现有 CSP，不新增自动网络请求。无 baseDir 的相对图片、缺失文件和不支持的格式显示可理解的占位，不阻断其他正文。异步图片和文本加载绑定 documentId 与内容 revision，过期结果不覆盖重新加载后的视图。

### D7: 页面排版与工作区外观分层

阅读器采用本项目独立设计 token：正文最大宽度 760 CSS px；侧边留白 clamp(16px, 4vw, 48px)；正文 16px、行高 1.75；H1/H2/H3 分别 2/1.5/1.25 倍正文。章节标题、公式、代码、表格分别控制间距，使用中文系统字体回退，正文不强制等宽。

readerAppearance 提供 follow-theme、paper、dark 三个值，默认 follow-theme。paper 为浅色页面／深色文字，dark 为深色页面／浅色文字，均限定在读视图；不改变 xterm ANSI palette、终端字号、当前全局主题或已有 CRT／ambient 设置。设置实时应用并持久化。

主工作区增加轻量间距、圆角内容面板与安静的非活跃导航，保留暖色 accent 和当前主题来源。Terminal 内容本身不加不透明遮罩，不通过降低文字透明度实现层次。阅读模式不显示 CRT 覆盖层，ambient 图层不能覆盖文档或降低可读性；已有装饰只在适当的终端／外框区域使用。

目录为读视图内可折叠导航，默认收起，宽度 200px；小窗口以弹出目录呈现，正文保持至少 320 CSS px 的阅读列。按钮同时有图标、可访问名称和键盘 focus 样式，中英文标签来自现有 i18n。图标区分终端、Markdown 文件和文本快照，不以单一颜色区分类型。

### D8: 文件加载、快照与持久化范围

文件与快照内容最大为 1 MiB UTF-8，沿用 Rust 文本限制；超过上限时在读取／解析前拒绝并说明原因，不截断成看似完整的正文。已有 read_text_file 若需要变更，采用最多上限加 1 byte 的读取保证实际读取也受限，保持原返回契约。文件读取、规范化与图片 I/O 放在 Rust blocking 任务；关闭或新 revision 后忽略旧结果。

新增版本化 logan.workspaceSnapshot 存储有序标签、活动标签、文件路径、预览模式及文件 companion 布局；全局 readerAppearance 仅由 settingsStore 保存，避免两份配置产生冲突。每个终端条目附带现有目录／树形快照，恢复时创建新的终端 tab／pane IDs 并重建引用。提取 tabSnapshot 纯序列化函数复用原布局限额，终端仍最多恢复 9 个，每标签最多 8 窗格；文件文档最多恢复 12 个，超限明确忽略额外恢复项。先验证类型、版本、深度和引用，再协调两个 store 初始化，避免先创建默认终端后再恢复一次。

无有效新快照时读取旧 logan.tabSnapshot 并转换为终端工作区条目；写新快照时继续镜像旧终端目录／布局键用于回滚。文档不写入旧终端树格式，不保存 PTY id、命令、Agent 状态或文本快照内容。引用临时快照的 companion 不恢复；临时活动标签消失后选最近仍存的条目。找不到的文件恢复为可关闭、可重试的错误文档，不阻止其他标签。

## Risks / Trade-offs

- [文档焦点仍沿用旧 activeTabId，导致后台写入或误关闭] → 在引入文档 UI 前完成焦点路由，检查 termBus、素材、drop、finder、快捷键和 launcher 等全部入口。
- [混合布局使 Terminal 重挂载] → 保持 App 与 PaneTree keyed 父层，用 PTY spawn／kill 调用次数、sessionId 和输出保留验证导航流程。
- [纯 DOM 长文档存在解析开销] → 1 MiB 上限、内容 revision memo、图片异步加载；用接近上限的真实结构文档记录加载与滚动表现，不预先加入虚拟化框架。
- [marked／KaTeX 扩展改变已有终端公式行为] → 保留旧 API，覆盖中文、代码变量、矩阵、重复标题、链接与错误公式的现有契约。
- [Review 草稿与磁盘文档内容不同] → 推广草稿为带来源标记的不可变快照；阅读器只读，保存继续在 Review 中完成，文件读视图显式重新加载。
- [原生公式字体与 KaTeX 存在视觉差异] → 验收阅读布局、清晰度与交互，不承诺像素复刻或未测量的性能优势。

## Migration Plan

1. 先建立文档记录、工作区协调与快照迁移，旧终端工作流仍可使用。
2. 接入焦点路由和主区阅读容器，验证存活 PTY 不重建，再加入全部打开入口。
3. 增强共享解析与媒体，再接入阅读样式、目录和即时设置。
4. 执行前后端检查及 macOS 实际交互验收，使用固定文档样例记录浅色、深色、分屏和最小窗口截图；Windows 验证缺失时明确记录为未验证。
5. 回滚时恢复原终端 UI 和依赖路径；旧 logan.tabSnapshot 镜像仍可恢复目录／布局，新工作区键保留，不删除用户设置与文档文件。

## Open Questions

无阻塞项。本轮按上述默认值实施；正文宽度和间距只在验收中根据实际中文文档可读性微调，保持规格要求。Agent Hook、文档搜索、虚拟化与可编辑主区文档另建后续 change。
